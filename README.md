# CSDC 官方网站

**Community Simulated Drift Competition**

CSDC（Community Simulated Drift Competition）是基于 Assetto Corsa 开展的虚拟漂移社区赛事。

本仓库为 CSDC 官方网站的源代码仓库，用于建设、维护和发布 CSDC 赛事相关的官方网站功能。

官方网站：**https://csdc.website/** 或在任意浏览器顶部搜索栏输入：csdc.website

---

## 一、项目介绍

CSDC 官方网站旨在为 CN 神力科莎的参赛车手、赛事组织者、模拟赛车爱好者以及 CSDC 的相关人员提供统一的信息发布与赛事管理平台。

网站涵盖赛事信息、车手资料、赛季管理、报名审核、车辆数据审核、赛事历史、资源下载及合作伙伴展示等功能。

项目最初由 HTML、CSS 和 JavaScript 构建，并在后续开发过程中逐步接入用户认证、数据库及邮件服务，形成了具有在线管理能力的赛事网站。

网站采用以黑、白、红为主的视觉风格，兼顾桌面端和移动端的使用体验。

## 二、网站主要功能

### 1. 赛事信息与展示

- **官方网站首页**：展示 CSDC 赛事信息、车手及合作伙伴。
- **赛事公示**：发布赛事安排、比赛日期、赛道及相关说明。
- **车手列表**：展示 CSDC 车手资料。
- **赛事历史**：记录过往赛事信息。
- **年度 TOP10**：展示年度车手排名与积分。
- **赛事排名与积分**：提供赛事排名相关信息。
- **公告与新闻**：发布赛事公告和社区消息。
- **资源下载**：集中提供赛事相关资源、文件及安装说明。
- **赛会介绍**：介绍 CSDC 赛事组织及相关信息。
- **赞助商与合作伙伴**：展示支持 CSDC 的品牌和组织。

### 2. 用户账号与车手管理

网站已接入用户账号系统，支持：

- 用户注册与登录
- 邮箱验证及密码重置
- 个人资料管理
- 账号与资料申请审核
- 正式车手资格审核

部分赛事功能需要用户完成相应的账号及车手资格审核后方可使用。

### 3. 赛季与赛事管理

网站支持以赛季为单位管理赛事和参赛车手，包括：

- 创建与管理赛季
- 赛季车号申请及审核
- 赛季正式车号绑定
- 分站赛事创建与管理
- 分站赛事报名及审核
- 赛事报名状态查询

赛季车号与指定赛季关联，不代表车手永久拥有该号码。

### 4. 车辆数据审核

为配合赛事车辆技术规范，网站提供车辆数据审核功能，包括：

- 车辆相关技术信息提交
- 车辆审核状态查询
- 管理员审核及驳回
- 车检联系方式展示
- 审核相关记录管理

具体车辆技术要求以 CSDC 当期赛事规则及官方公告为准。

### 5. 管理员后台

网站设有专用管理员后台，负责用户、车手、赛季和赛事等业务的管理。

目前包括以下管理模块：

1. 用户账号审核
2. 资料申请审核
3. 车手资格审核
4. 赛季管理
5. 赛季车号审核
6. 分站赛事管理
7. 分站赛事报名审核
8. 车辆数据审核
9. 查看或更改车检联系方式
10. 查看操作日志

管理员后台还提供部分业务记录的强制删除功能，包括删除前影响范围预览、二次确认及数据库权限检查。

相关操作仅供授权管理员使用。

## 三、技术架构

本项目以原生 Web 技术为基础，无需依赖大型前端框架。

| 技术或服务 | 主要用途 |
|---|---|
| HTML5 | 页面结构 |
| CSS3 | 页面样式与响应式布局 |
| JavaScript | 前端交互及业务逻辑 |
| GitHub | 源代码托管与版本管理 |
| GitHub Pages | 静态网站托管 |
| GitHub Actions | 自动化部署 |
| Supabase | 用户认证、数据库及后台业务 |
| Resend | 邮件发送服务 |

### 网站部署

网站源代码托管于 GitHub，并通过 GitHub Pages 和 GitHub Actions 发布。

一般情况下，静态页面修改后可以通过提交 GitHub 仓库触发部署，无需额外安装服务器端 Web 框架。

### 数据管理

网站采用静态内容与在线数据库相结合的方式：

- 部分赛事展示、页面内容及资源信息通过 GitHub 仓库中的文件维护。
- 用户账号、车手资格、赛季车号、赛事报名及车辆审核等业务数据由 Supabase 管理。
- 管理员通过受权限控制的后台功能处理相关业务。

因此，并非所有网站内容都需要通过修改 GitHub 文件更新。

如需修改或部署本项目，请注意：

- 保持现有业务接口与数据库结构的兼容性。
- 修改数据库或管理员权限相关功能前，应做好备份。
- 不要将 Supabase Service Role Key、Resend API Key、数据库密码或其他服务端密钥提交至公开仓库。
- 涉及删除、审核和权限管理的功能应在充分测试后部署。
- 网站公开源代码不代表所有业务数据和管理权限均可公开访问。
